How to solve any logic exam question

Knowing syntax is not enough - interviewers watch how you think. Use this method every time. It works for JavaScript, SQL and pen-and-paper puzzles.

1. Understand2. Examples3. Brute force 4. Optimise5. Code6. Test

1. Understand

  • Restate the problem in your own words.
  • Identify the input (type, size, range) and the output (type, format).
  • Ask: Can it be empty? Negative? Duplicates? Already sorted? Very large?

2. Examples

Write 2-3 tiny examples by hand, including one edge case.

twoSum([2, 7, 11, 15], 9)  ->  [0, 1]
twoSum([3, 3], 6)          ->  [0, 1]
twoSum([1], 5)             ->  null     // edge case

3. Brute force

Say the simplest correct solution out loud, even if it is slow: "Check every pair with two loops - O(n2)." A working slow answer beats an unfinished fast one.

4. Optimise - ask these questions

QuestionOften leads to
Am I searching for something over and over?Hash map / Set (lesson 07)
Is the input sorted, or can I sort it?Binary search / two pointers (04, 09)
Am I looking at a contiguous range?Sliding window / prefix sums (04)
Do I need the "most recent" or matching pair?Stack (10)
Does the problem repeat on smaller inputs?Recursion + memoization (03)
Is it a grid, map or network?2D array + BFS/DFS (05)
Am I recomputing the same thing?Cache it (Map, prefix array)

5. Code

  • Use clear names (left, right, seen, count), not a, b, x.
  • Handle edge cases at the top: if (arr.length === 0) return null;
  • Extract small helper functions when a step has a name.

6. Test

  • Trace your code line by line with your examples.
  • Check edge cases: empty, one element, all equal, negatives, very large.
  • State the final time and space complexity - interviewers always ask.

The SQL version

  1. Which tables hold the data? Which columns link them?
  2. What does one output row represent - one employee? one department?
  3. Build in execution order: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
  4. Check mentally on a small case. Watch for NULL and duplicated rows from joins.

Classic logic puzzles - practise out loud

8 balls, one is heavier. Find it with a balance scale in 2 weighings.

Weigh 3 vs 3. If they balance, weigh the remaining 2 - the heavier one wins. If they don't, take the heavier group of 3 and weigh 1 vs 1: the heavier wins, or the third ball if they balance. It's the same "split into groups and eliminate" idea as binary search.

Two ropes each take 60 minutes to burn (unevenly). Measure 45 minutes.

Light rope A at both ends and rope B at one end. A burns out after 30 minutes. Then light the other end of B - it burns out 15 minutes later. Total: 45.

Number sequence: 2, 6, 12, 20, 30, ?

Differences are 4, 6, 8, 10, so the next difference is 12: 42. The formula is n × (n + 1).

All roses are flowers. Some flowers fade quickly. Can we conclude that some roses fade quickly?

No. The flowers that fade quickly might all be non-roses. In set terms: Roses ⊆ Flowers and Fading ∩ Flowers ≠ ∅ does not imply Fading ∩ Roses ≠ ∅.

A knight always tells the truth, a knave always lies. A says "We are both knaves." What are A and B?

If A were a knight the statement would be true, making A a knave - a contradiction. So A is a knave, the statement is false, so they are not both knaves: B is a knight.

You have a 3-litre and a 5-litre jug. Measure exactly 4 litres.

Fill the 5, pour into the 3 (5 has 2 left). Empty the 3, pour the 2 in. Fill the 5 again and top up the 3 (needs 1). The 5-litre jug now holds 4.

A bat and a ball cost $1.10 in total. The bat costs $1.00 more than the ball. How much is the ball?

Not 10 cents! ball + (ball + 1.00) = 1.10, so 2 × ball = 0.10: the ball costs 5 cents. Lesson: write the equation instead of trusting intuition.
